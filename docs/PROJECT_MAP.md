# PROJECT MAP — Transport Telemetry

Собственная система GNSS-мониторинга общественного транспорта. MVP — один трекер, сервер, карта и симулятор. Целевые масштабы из SRS — до 5 000 трекеров и 10 000 одновременных клиентов. В номинальном режиме поступает одна координата в секунду. [Системные требования](SRS.md)

## Потоки

```text
GNSS → трекер → POSITION_V1 (UDP) → текущее состояние → карта
              └→ локальный журнал → ARCHIVE_TRANSFER (TCP/TLS) → архив
трекер → TX_SUMMARY → сервер
трекер ← RX_SUMMARY ← сервер, независимо от TX
трекер ↔ сервер через TLS для выдачи диапазонов и обновления ключей
защищённое управление и OTA ↔ сервер (полный контракт OPEN)
```

Трекер и автобус — разные сущности. Сервер хранит их привязку. Пара `(trackerId, sequence)` связывает позицию live с архивной записью. Сервер публикует валидную live-позицию только при росте `sequence` трекера. При отсутствии обновлений карта отмечает устаревание. Архивная выгрузка пополняет историю независимо от текущей позиции и live RX. [Контракт позиции](icd/POSITION_V1.md#live-доставка) · [Архив](icd/ARCHIVE_TRANSFER.md#граница-с-live)

Форматы и статусы интерфейсов перечислены в [Master ICD](icd/README.md). За идентификацию устройства, авторизацию и работу с ключами отвечает [KEY_MANAGEMENT](security/KEY_MANAGEMENT.md).

## Будущие области проектирования

| Область | Статус |
| --- | --- |
| Мониторинг доступности | **APPROVED** как потребность. Модель **PROPOSED**, пороги и канал оповещения **OPEN**. |
| Длительные стоянки | Обнаружение **APPROVED** как потребность. Пороги и реакции **OPEN**. Молчание трекера оставляет факт стоянки неопределённым. |
| Питание и RTC | Независимость питания от зажигания, резерв RTC и принципы синхронизации **APPROVED**. Схема питания и параметры **OPEN**. |
| Режимы работы и ночные рейсы | Ночные рейсы **APPROVED** как ограничение. Выбор режима по состоянию рейса **PROPOSED**, критерии переходов **OPEN**. |

Решения по этим областям собраны в [DECISIONS](DECISIONS.md#будущие-области-проектирования).
