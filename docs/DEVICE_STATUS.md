# DEVICE_STATUS (рабочее название)

В плане интерфейсов предусмотрено отдельное сообщение состояния трекера. В каталоге оно обозначено `DEVICE_STATUS` (ICD-007).
## Назначение

Сообщение предназначено для передачи состояния трекера независимо от наличия пригодной GNSS-позиции. По нему сервер сможет различать связь с устройством и доступность GNSS-фиксации.

Доступность устройства по-прежнему определяется сервером по фактически полученным сообщениям и правилам тайм-аутов, а не только заявленным трекером состоянием.

## Границы и связи

- При добавлении ICD-007 сохраняется действующая [структура POSITION_V1](POSITION.md#binary-layout). [Условия формирования позиции](POSITION.md#horizontal-accuracy) действуют независимо от сообщений состояния.
- [Локальный журнал](POSITION_RECORD.md#purpose) определяет диагностику отсутствия фикса.
- Тема связана с мониторингом доступности трекеров в [DECISIONS](DECISIONS.md#open-questions).
- За получение сведений об устройстве отвечает отдельный защищённый обмен [`DEVICE_INFO_REQ` / `DEVICE_INFO_RESP`](DECISIONS.md#device-info) в ICD-006.

## Что ещё определить

| Область | Что предстоит определить | Обсуждаемый вариант |
| --- | --- | --- |
| Заголовок | Постоянное имя, `messageType`, версия, структура заголовка, принадлежность к семейству пакетов. | Рабочее имя `DEVICE_STATUS`. |
| Тело | Поля состояния, идентификация трекера, временные метки и диагностика, длина. | |
| Формирование | Условия начала и прекращения отправки, частота и связь с `POSITION`, порог отсутствия позиции и переключение режимов. | При работающей связи сообщать о потере и восстановлении фикса по изменению состояния. При отсутствии координат периодически отправлять heartbeat для подтверждения связи. |
| Доставка | Транспорт, приоритет, подтверждения, аутентификация, шифрование и защита от повторов. | |
| Обработка на сервере | Семантика `lastSeen`, no-fix, stale и offline, пороги и реакции. | |
