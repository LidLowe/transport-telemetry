# Process Flow

Когда трекер и сервер используют сообщения из [Master ICD](ICD.md#messages).

## Сценарии

| Сценарий | Когда | Обмен и результат |
| --- | --- | --- |
| [Выдача диапазона](POSITION.md#range-allocation) | Трекер запустился или заранее запрашивает следующий диапазон. | Трекер отправляет `RANGE_REQ`. Сервер отвечает `RANGE_RESP` при выдаче или `RANGE_ERR` при отказе. |
| [Потерян ответ о диапазоне](POSITION.md#range-allocation) | Трекер ждёт ответ в рамках того же запуска. | Трекер повторяет тот же `RANGE_REQ`. Повтор успешной выдачи возвращает тот же диапазон. |
| [Отправка позиции](POSITION.md#live-publication) | Готово новое достоверное измерение, есть номер и [рабочий ключ](KEY_MANAGEMENT.md#tls-exporter). | Трекер отправляет `POSITION`. Сервер обновляет live-позицию, когда получает валидную позицию с большим номером. |
| [Диагностика доставки](TX_RX_STATS.md#reporting-flow) | Завершилась учётная минута. | Трекер отправляет `TX_STATS` серверу. Сервер независимо отправляет `RX_STATS` трекеру. Сводки сопоставляют позже. |
| [Потеря и восстановление связи](POSITION.md#range-allocation) | Сеть недоступна, затем возвращается. | Пока доступны номера, трекер пишет измерения в [локальный журнал](POSITION_RECORD.md). После восстановления связи свежие позиции идут через `POSITION`, история выгружается отдельно. |
| [Выгрузка истории](ARCHIVE_TRANSFER.md#ack-and-resume) | Пришло время выгрузки и связь позволяет отправить журнал. | Трекер отправляет `ARCHIVE_BLOCK`. Успешный `ARCHIVE_ACK` от сервера подтверждает устойчивое сохранение всего блока. |
| [Потеря подтверждения архива](ARCHIVE_TRANSFER.md#ack-and-resume) | Трекер не получил `ARCHIVE_ACK`. | Трекер может повторить тот же `ARCHIVE_BLOCK`. Сервер подтверждает уже сохранённый блок без дублей. |
| [Смена рабочего ключа](KEY_MANAGEMENT.md#rekey) | Плановая ротация или восстановление ключевого контекста. | Трекер отправляет `REKEY_REQ`. После успешного `REKEY_RESP` он может отправлять новые `POSITION` с новым ключом. |
| [Сведения об устройстве](DECISIONS.md#device-info) | Серверу нужны данные о трекере, например версия прошивки. | Сервер отправляет `DEVICE_INFO_REQ`. Трекер возвращает сведения в `DEVICE_INFO_RESP`. |
